## PRIV: privacy under a cloud-only rule (new agent, Opus 5.5 high for the design, Sonnet 5.5 high for the build)

**The honest starting point.** With cloud models only, anything the model sees leaves this Mac. No design can make that zero. What we can do is send less, send it with identifiers removed, ask before sending the sensitive kinds, never send the things that must never leave, and keep a record the owner can audit. Today only secrets are scrubbed (`DlpFilter`); the "private agents stay local" promise (`_LOCAL_ONLY_AGENTS`, `force_local`) is false and must be removed from code, prompts and UI.

**Design (one gate every cloud call passes through, in `governance.py` and `dispatch.py`):**

1. **Tiers.** Every tool result and every attachment is tagged when it enters a turn: T0 public (web pages, news, search), T1 personal (calendar entries, file names, goals, notes you wrote for the model), T2 sensitive (mail bodies, memory vault, documents and Drive content, finance, health, contacts), T3 never (password vault, Keychain items, `.env` and keys, SSH keys, browser cookies and tokens, owner secret, card and bank numbers). T3 never leaves: the existing hard deny-lists are extended and tested. T2 needs consent. T1 and T0 pass after redaction.
2. **Minimise.** T2 sources return the least that answers the task: a mailbox search returns subjects and a short snippet first, the model asks for one body at a time, attachments are off unless asked, long documents are cut to the relevant part, never the whole archive in one turn.
3. **Reversible redaction before send.** Besides secrets, replace personal identifiers by placeholders: card and IBAN numbers, government and tax IDs, phone numbers, street addresses, and email addresses of people other than the owner become `[EMAIL_1]`, `[PHONE_2]` and so on; the mapping stays in memory on this Mac for the turn, and placeholders in the model's reply or tool arguments are mapped back locally. Names and free text are not reliably removable; the plan says so in the UI.
4. **Consent.** First time a T2 source feeds a cloud turn, the owner is asked once per source (Mail, Memory, Documents and Drive, Finance, Contacts) with a clear sentence: what is sent, to which provider. The choice is a visible toggle in SETTINGS. A per-chat **Private mode** disables all T2 tools for that chat. Bulk reads (more than a set number of items) always ask.
5. **Provider control.** SETTINGS shows a provider table (which cloud provider each backend uses, region where known, and whether the account's data-retention and training settings have been verified by the owner). The code cannot verify a provider's retention; this is an owner checklist item for each key (Ollama Cloud, Gemini, Claude CLI sign-in).
6. **Egress ledger.** Every cloud call writes a metadata record (time, provider, tier counts, bytes, number of redactions, source names) to a local file shown in SECURITY. Content is not stored, only the metadata and a hash.
7. **Untrusted-content rule.** Pages, mail and files are data, not instructions (already in the tool guide); sending anything out through browser or tools stays behind the existing outbound scan.
8. **Remove the false promise.** `force_local`, `_LOCAL_ONLY_AGENTS` routing, and every "stays local" claim about model use are deleted or reworded (storage claims, like "the vault never leaves this Mac", stay and are tested).

**Findings it closes:** A-13, P5-31, PRIV-1 to PRIV-5. **Exit test:** a test sends a mailbox sample through a stubbed provider and shows (a) T3 content absent, (b) identifiers replaced, (c) a T2 turn refused until consent, (d) the ledger row written, (e) Private mode blocks T2 tools.

# Dourmouse fix plan: every finding, plus an active hunt for more (2026-10-06)

Source of truth for the work items: `CODE_ISSUES_2026-10-06.md` (288 findings: 8 high, 119 medium, 161 low) and `FIX_LEDGER_2026-10-06.md` (one row per finding with a Status column). Nothing in the ledger may be dropped, merged away or closed without the evidence rule below.

## Rules for this plan

1. **Every finding gets fixed.** The ledger has one row per finding id. A row is closed only with: a failing-then-passing test, or (for things a test cannot show) a recorded live observation, plus the commit. "Cannot reproduce" is a result that must be written into the row with what was tried; it is not a close.
2. **No dismissals by agents.** A builder may mark a finding `needs-decision` (it conflicts with a documented policy or needs the owner) or `needs-backend`, with the exact question. Only the owner can change a finding to `accepted risk`.
3. **Fixing is not finishing.** After every fix wave: one read-only reviewer, then the full suite (two halves, `--timeout=120 --timeout-method=thread`), a numbered finding in `ENGINEERING_AUDIT.md`, roadmap line, commit, push, backup, tracking docs. Same hard rules as before (one checkout, no ports 8765/9333/9334, no pkill).
4. **Every wave also hunts.** Each fixing agent, after its list, must read the neighbouring code of every file it touched (callers, callees, sibling functions) looking for the same defect class, and record new findings as `<AGENT>-N+` rows in the ledger. A bug class found once is searched for everywhere with Grep.
5. **Order:** security and silent data loss first, then correctness, then robustness, then optimisation. Highs first inside each agent.
